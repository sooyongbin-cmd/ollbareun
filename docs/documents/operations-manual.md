# 올바름 인력관리시스템 운영 매뉴얼

## 1. 운영 직군

| 직군 | 주요 업무 |
| --- | --- |
| 관리자 | 직원·근무지·배정·교육·점검·리포트·계정 관리 |
| 시스템 운영 담당자 | 배포, 환경변수, DB, 로그, 장애 대응, 백업 관리 |
| 현장 근무자 | 출퇴근, 교육 이수, 점검, 특이사항 보고 |

## 2. 일상 운영

### 2.1 직원과 배정

1. 직원 등록 시 이름, 연락처, 직무를 확인한다.
2. 퇴직자는 삭제보다 퇴직 상태 처리를 우선한다.
3. 근무지 주소와 GPS 좌표, 출근 인정 반경을 확인한다.
4. 직원별 배정 시작일과 종료일이 겹치지 않게 등록한다.

#### 2.1.1 배정등록 저장 시 근무일·휴무일·출퇴근 예정시각 기준

배정등록을 저장하면 선택한 직원의 근무형태와 출퇴근 시간을 기준으로 배정기간의 날짜별 예정시각이 생성된다. 배정등록 화면에 표시되는 출근·퇴근 시간은 직원 정보에 설정된 값을 기본으로 하며, 저장 시 배정의 기준 시간으로 함께 보관한다. 시간이 별도로 전달되지 않는 경우에는 직원 정보의 출퇴근 시간을 사용한다. 날짜별 예정시각은 한국 시간 기준으로 관리한다.

| 근무형태 | 배정 저장 시 적용 기준 |
| --- | --- |
| 일반근무(0) | 배정기간의 모든 날짜에 출근 예정시각과 퇴근 예정시각을 생성한다. 토·일 및 공휴일을 자동 휴무로 처리하지 않는다. |
| 24시간근무(1) | 배정 시작일을 기준으로 하루씩 교대한다. 시작일에서 0일, 2일, 4일처럼 짝수 번째 날짜에는 출근 예정시각을, 1일, 3일, 5일처럼 홀수 번째 날짜에는 퇴근 예정시각을 생성한다. |
| 야간근무(2) | 토요일·일요일 또는 공휴일 관리에서 `선택=Y`인 날짜를 자동 휴무일로 등록한다. 휴무일에는 출근 예정시각을 만들지 않으며, 전날 출근 예정이 있으면 해당 날짜에는 퇴근 예정시각만 만든다. 전날 출근 예정이 없으면 출퇴근 예정시각을 만들지 않는다. |

야간근무의 휴무일 판단은 공휴일 API에서 내려온 날짜 자체가 아니라 공휴일 관리 목록에서 `선택` 값이 `Y`인 날짜를 기준으로 한다. 공휴일이지만 `N`으로 저장된 날짜는 자동 휴무 대상이 아니다. 수동 휴무일 지정은 **근무지배정 상세** 화면의 휴무일 캘린더에서 근무기간 안의 날짜를 선택해 저장하며, 저장된 날짜에는 근무자의 출근을 허용하지 않는다.

출퇴근 예정시각은 `work_assignment_daily_attendance`에 날짜별로 저장되며, 야간근무의 휴무일 처리를 포함해 이후 출결 등록과 근태 판정의 기준으로 사용한다. 배정 저장 후 **근무지배정 상세** 화면의 달력에서 날짜별 출근·퇴근 예정시각과 휴무일 표시를 확인한다.

#### 2.1.2 관리자 상세 화면 명칭

목록에서 자료를 선택해 확인·수정하는 화면은 다음 명칭으로 표시한다.

| 대상 | 화면 제목 |
| --- | --- |
| 직원 | 직원 상세 |
| 근무지 | 근무지 상세 |
| 근무지 배정 | 근무지배정 상세 |
| 교육자료 | 교육자료 상세 |
| 근태 기록 | 근태 상세 |
| 시스템 설정 | 시스템설정 상세 |

따라서 배정의 날짜별 예정시각과 휴무일을 확인할 때는 **근무지배정 상세** 화면을 사용한다.

### 2.2 근태

- 대시보드에서 당일 출근·결근·지각 현황을 확인한다.
- 근태 리포트의 직원명·연도 조건으로 이력을 조회한다.
- GPS 오류 신고 시 기기 위치 권한, 당일 배정, 근무지 좌표와 반경을 순서대로 점검한다.

#### 2.2.1 대시보드 출근현황 카드의 출근·결근·지각 집계 기준

대시보드 첫 번째 **출근현황** 카드의 분모는 현재 재직 직원 전체가 아니다. `work_assignment_daily_attendance`에서 오늘 날짜(`work_date`)의 출근 예정시각(`intime`)이 있는 배정을 조회하고, 해당 배정의 직원 ID를 연결해 오늘 출근 예정인 재직 직원 수를 계산한다. 같은 직원이 여러 행으로 조회되더라도 직원 ID 기준으로 한 번만 집계한다.

| 카드 항목 | 산출 기준 |
| --- | --- |
| 출근 | 오늘 출근 기록이 있고 아직 퇴근하지 않은 재직 직원 수 |
| 분모 | 오늘 `work_assignment_daily_attendance`에 `intime`이 있는 배정의 재직 직원 수 |
| 대기 | 출근 예정시각이 현재 시각과 같거나 이후이고, 해당 직원의 오늘 출근 근태자료가 없는 재직 직원 수 |
| 결근 | 출근 예정시각이 현재 시각보다 이전이고, 해당 직원의 오늘 출근 근태자료가 없는 재직 직원 수 |
| 지각 | 출근 예정시각보다 늦은 출근 근태자료가 있는 재직 직원 수 |

따라서 카드에는 `출근 X/Y 명 대기A명 결근Z명 지각W명` 형식으로 표시된다. 예를 들어 `출근 1/2 명 대기1명 결근1명 지각0명`은 현재 출근 1명, 오늘 출근 예정 2명, 아직 예정시각 전이라 대기 중인 직원 1명, 예정시각이 지난 결근 1명, 예정시각 이후 출근한 지각 0명을 의미한다. 휴무일 등으로 해당 날짜의 `intime`이 없는 배정은 분모와 대기·결근·지각 집계에 포함하지 않는다. 직원 ID 기준으로 집계하므로 동일 직원이 여러 배정 행에 있어도 한 번만 센다.

이 카드의 `출근`은 현재 미퇴근 인원 수이고, `지각`은 별도 판정 수치다. 따라서 지각한 직원이 현재 미퇴근이면 `출근`과 `지각`에 함께 포함될 수 있다. 대기는 예정시각이 지나지 않은 상태이며, 예정시각이 지나면 출근자료가 없는 직원을 결근으로 집계한다. 이 기준은 직원관리 화면의 재직 직원 수 및 최근 30일 추이 차트의 전체 재직 직원 기준과 다를 수 있다.

#### 2.2.2 근태관리의 `지각` 판정 기준

근태관리 목록은 다음 조건을 모두 만족하는 배정의 예정 출근시각과 실제 출근일시를 비교한다.

1. 같은 직원이다.
2. 같은 근무지이다.
3. 같은 근무일이다.
4. 해당 날짜의 배정별 예정 출근시각(`intime`)이 존재한다.

실제 출근일시가 예정 출근시각보다 늦으면 목록의 상태에 `지각`을 표시한다. 예정시각과 같거나 이르면 `지각`으로 표시하지 않는다. 예정 출근시각이 없는 휴무일, 배정과 일치하지 않는 근태기록, 출근일시가 없는 기록은 지각으로 판정하지 않는다. 근태기록을 수정한 경우 다음 목록 조회에서 수정된 출근일시를 기준으로 다시 판정하며, 엑셀 다운로드에도 동일한 상태가 포함된다.

#### 2.2.3 출근현황 목록의 상태 표시

**출근현황** 화면은 날짜를 기준으로 `work_assignment_daily_attendance`에 출근 예정시각(`intime`)이 있는 재직 직원만 목록에 표시한다. 목록의 `출근시각`은 출근 근태자료의 실제 출근시각이며, 자료가 없으면 `-`로 표시한다.

| 상태 | 표시 기준 |
| --- | --- |
| 출근 | 실제 출근일시가 예정 출근시각과 같거나 이른 경우 |
| 지각 | 실제 출근일시가 예정 출근시각보다 늦은 경우 |
| 대기 | 출근 근태자료가 없고 출근 예정시각이 현재 시각과 같거나 이후인 경우 |
| 결근 | 출근 근태자료가 없고 출근 예정시각이 현재 시각보다 이전인 경우. 기존 `미출근` 표기를 `결근`으로 변경했다. |

목록은 출근 예정시각이 빠른 순서로 정렬하며, 같은 시각에는 직원 이름순으로 표시한다. 목록의 `대기`·`결근` 표시는 출근자료 유무와 현재 시각을 함께 반영하며, 대시보드 카드의 결근 수는 현재 시각이 예정 출근시각을 지났는지까지 확인해 집계한다.

### 2.3 안전교육

- 교육 제목과 재생 가능한 영상 링크를 등록한다.
- 직원별 전체·이수·미이수 건수를 확인한다.
- 미이수 알림 발송 전 대상 인원과 구독 상태를 확인한다.
- 자동 발송 실패 시 실행 이력의 오류 사유를 확인하고 수동 발송을 검토한다.

### 2.4 점검과 특이사항

- 점검 현장을 근무지에 연결하고 QR 정보를 생성한다.
- 점검 이력은 최신 순으로 확인하고 필요 시 근무지로 필터링한다.
- 특이사항 보고의 내용, 사진, 위치와 Naver mail 전달 상태를 확인한다.
- 보고 삭제 시 연결 사진도 함께 삭제되므로 대상 내용을 다시 확인한다.

## 3. 계정 및 설정 관리

- 관리자 계정은 업무상 필요한 사용자만 등록한다.
- 담당자 변경 또는 퇴사 시 관리자 계정을 즉시 정리한다.
- 시스템 설정 코드는 운영 기능에서 참조하므로 의미를 확인한 후 수정한다.
- 비밀번호와 서비스 키는 문서나 메신저에 평문으로 공유하지 않는다.

### 3.1 네이버 메일 발신 계정 등록 및 변경

특이사항 보고에 사용할 네이버 발신 계정을 새로 등록하거나 교체할 때 다음 순서로 진행한다. 현재 구현에서는 코드 수정 없이 네이버 계정 설정과 Vercel 환경변수 변경으로 적용할 수 있다.

#### 1. 네이버 2단계 인증과 애플리케이션 비밀번호 준비

1. 발신용 네이버 계정으로 로그인한다.
2. 네이버 계정의 보안설정에서 2단계 인증을 활성화한다.
3. 애플리케이션 비밀번호를 발급한다. SMTP 인증에는 일반 로그인 비밀번호가 아닌 이 비밀번호를 사용한다.

네이버는 2025년 6월 24일부터 외부 메일 연동에 2단계 인증과 애플리케이션 비밀번호를 요구한다. 자세한 절차는 [네이버 공식 FAQ](https://help.naver.com/service/30029/contents/24347?lang=ko&osType=COMMONOS)를 참고한다.

#### 2. 네이버 메일에서 SMTP 사용 허용

1. PC 네이버 메일의 **환경설정 → POP3/IMAP 설정 → POP3/SMTP 설정**으로 이동한다.
2. **POP3/SMTP 사용**을 **사용함**으로 변경하고 저장한다.
3. SMTP 서버는 `smtp.naver.com`, 포트는 `465`, 보안 연결은 SSL을 사용한다.

[네이버 SMTP 설정 안내](https://help.naver.com/service/30029/contents/21341?lang=ko&osType=PC)

#### 3. Vercel 환경변수 등록

Vercel의 해당 프로젝트에서 **Settings → Environment Variables**로 이동하여 아래 값을 등록하거나 변경한다. 운영 사이트에는 **Production** 환경으로 적용한다.

| 환경변수 | 입력할 값 | 비고 |
| --- | --- | --- |
| `NAVER_SMTP_USER` | 새 발신 계정 이메일, 예: `example@naver.com` | 필수 |
| `NAVER_SMTP_PASSWORD` | 네이버에서 발급한 애플리케이션 비밀번호 | 일반 로그인 비밀번호 사용 불가 |
| `NAVER_SMTP_PORT` | `465` | 필수. 현재 코드는 이 포트에서 SSL 사용 |
| `NAVER_SMTP_FROM` | 새 발신 계정 이메일 | 생략하면 `NAVER_SMTP_USER` 사용. 계정 교체 시 기존 주소가 남지 않도록 확인 |

애플리케이션 비밀번호는 환경변수로만 저장하며 GitHub 코드, 프로젝트 문서, 메신저에 기록하지 않는다. SMTP 서버 주소는 코드에서 `smtp.naver.com`으로 지정되어 있으므로 별도 환경변수를 추가할 필요가 없다.

#### 4. 보고서 수신 주소 설정

1. [관리자 시스템설정](https://ollbareun.vercel.app/manager/system/configs)으로 이동한다.
2. 시스템코드 **`manager_email`**의 내용을 보고서를 받을 이메일 주소로 설정한다.

발신 계정은 Vercel 환경변수에서, 수신 주소는 시스템설정의 `manager_email`에서 관리한다. 수신 주소만 변경한다면 네이버 발신 계정을 새로 등록하거나 SMTP 환경변수를 변경할 필요가 없다.

#### 5. 재배포 및 수신 확인

1. 환경변수 저장 후 Vercel에서 **Redeploy**를 실행한다. 환경변수 변경은 새 배포부터 적용된다. [Vercel 환경변수 안내](https://vercel.com/docs/environment-variables)
2. 배포 완료 후 근무자의 **특이사항** 화면에서 테스트 보고를 작성한다. 관리자에게 테스트임을 알 수 있도록 내용에 **메일 설정 테스트**를 명시한다.
3. **보고하기**를 누르고 완료 안내에서 NAVER 이메일 발송 결과를 확인한다.
4. `manager_email`에 설정한 수신 계정의 받은편지함과 스팸함에서 실제 수신 여부를 확인한다.

현재 **보고하기**는 보고서를 한 번 저장한 뒤 관리자 푸시알림 전송을 시도하고, 이어서 NAVER 이메일을 전송한다. 따라서 테스트 보고도 관리자 푸시알림이 함께 발송된다. 푸시 전송 실패 시에도 이메일 발송은 시도하며, 완료 안내에서 두 결과를 각각 확인할 수 있다.

#### 발송 실패 시 확인 사항

- 네이버 계정의 2단계 인증 및 POP3/SMTP 사용 설정을 확인한다.
- `NAVER_SMTP_PASSWORD`에 유효한 애플리케이션 비밀번호가 입력되어 있는지 확인한다.
- `NAVER_SMTP_USER`와 `NAVER_SMTP_FROM`이 새 발신 계정으로 설정되어 있는지 확인한다.
- `NAVER_SMTP_PORT`가 `465`인지, 환경변수가 Production에 적용되어 있는지 확인한다.
- 환경변수 변경 후 재배포했는지 확인한다.
- `manager_email`의 수신 주소, 스팸함 및 Vercel 오류 로그를 확인한다.

### 3.2 공휴일 정보 API 신청 및 설정

1. [공공데이터포털 한국천문연구원 특일 정보](https://www.data.go.kr/data/15012690/openapi.do)에 접속하고 로그인합니다.
2. **활용신청**을 선택하여 사용 목적과 필요한 신청 항목을 입력합니다. 신청한 서비스의 승인 상태와 이용 가능한 호출 한도를 확인합니다.
3. 마이페이지의 OpenAPI 활용 내역에서 해당 서비스의 **일반 인증키(Decoding)**를 확인합니다. 인증키는 공개 문서나 GitHub에 올리지 않습니다.
4. Vercel 프로젝트의 Settings → Environment Variables에 서버 환경변수 **DATA_GO_KR_SERVICE_KEY**를 만들고 인증키를 값으로 등록합니다. 운영 서비스는 Production 환경에 적용합니다. 변수 이름에 NEXT_PUBLIC_을 붙이지 않습니다.
5. 환경변수를 저장한 뒤 재배포(Redeploy)합니다. 로컬 개발 시에는 같은 변수를 커밋하지 않는 .env.local에 설정합니다.
6. 관리자 → 직원관리 → **공휴일관리**에서 연도를 입력하고 **공휴일가져오기**를 누릅니다. 확인창에서 해당 연도를 확인하고 승인합니다.

공휴일 조회 기능(getRestDeInfo)으로 해당 연도의 자료를 받아 공휴일 여부가 Y인 날짜만 저장합니다. 신규 날짜의 선택값은 Y이며, 이미 존재하는 날짜는 수정하지 않고 건너뜁니다. 다시 가져와도 기존 이름과 선택값은 유지됩니다. 결과 메시지에서 등록 건수와 건너뛴 건수를 확인합니다.

목록의 **선택** 체크박스를 변경하면 Y/N 값이 즉시 저장됩니다. **휴일추가**에서는 날짜를 입력하여 선택값 Y로 직접 등록할 수 있습니다. 중복 날짜는 등록되지 않습니다. 공휴일 선택값은 야간근무(2)의 배정 저장 시 일정 생성에 자동 반영됩니다. 선택값이 `Y`인 공휴일은 주말과 같은 휴무일 기준으로 처리됩니다. 일반근무(0)와 24시간근무(1)은 공휴일·주말을 자동 휴무로 처리하지 않으므로 필요한 경우 **근무지배정 상세** 화면에서 휴무일을 수동 지정합니다.

인증키가 없으면 설정 안내가 표시됩니다. 가져오기 실패 시 활용승인 여부, 인증키, 요청 한도, 공공데이터포털 서비스 상태를 확인합니다. 임시공휴일 등 변경 사항이 발표되면 해당 연도를 다시 가져오고, 기존 자료의 변경이 필요한 경우에는 선택값을 직접 조정합니다. API 등록 정보와 제공 범위는 공공데이터포털의 최신 안내를 기준으로 확인합니다.

## 5. 장애 대응

1. 발생 시각, 사용자, 화면, 재현 절차와 오류 문구를 확보한다.
2. 전체 장애인지 특정 사용자·기기·근무지 문제인지 구분한다.
3. Vercel 로그, Supabase 상태와 외부 서비스 상태를 확인한다.
4. 데이터 손상 가능성이 있으면 쓰기 작업을 제한하고 백업을 확보한다.
5. 복구 후 원인, 영향, 조치, 재발 방지 내용을 기록한다.
