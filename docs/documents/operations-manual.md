## 2. 일상 운영

### 2.1 직원과 배정

1. 직원 등록 시 이름, 연락처, 직무를 확인한다.
2. 퇴직자는 삭제보다 퇴직 상태 처리를 우선한다.
3. 근무지 주소와 GPS 좌표, 출근 인정 반경을 확인한다.
4. 직원별 배정 시작일과 종료일이 겹치지 않게 등록한다.

#### 2.1.1 배정등록 저장 시 근무일·휴무일·출퇴근 예정시각 기준

배정등록을 저장하면 선택한 직원의 근무형태와 출퇴근 시간을 기준으로 배정기간의 날짜별 예정시각이 생성된다. 배정등록 화면에 표시되는 출근·퇴근 시간은 직원 정보에 설정된 값을 기본으로 하며, 저장 시 배정의 기준 시간으로 함께 보관한다. 시간이 별도로 전달되지 않는 경우에는 직원 정보의 출퇴근 시간을 사용한다. 날짜별 예정시각은 한국 시간 기준으로 관리한다.

| 근무형태 | 배정 저장 시 적용 기준 |
| --- | --- |
| 일반근무(0) | 배정기간의 모든 날짜에 출근 예정시각과 퇴근 예정시각을 생성한다. 토·일 및 공휴일을 자동 휴무로 처리하지 않는다. |
| 격일근무(1) | 배정 시작일부터 하루씩 교대한다. 짝수 번째 날짜(시작일 포함)에만 근무기록을 만들고, 해당 행에 출근 예정시각과 다음 날 퇴근 예정시각을 함께 저장한다. 홀수 번째 날짜에는 별도 근무기록을 만들지 않는다. |
| 야간근무(2) | 토요일·일요일 또는 공휴일 관리에서 `선택=Y`인 날짜를 자동 휴무일로 등록한다. 출근일에 한 건을 생성하고 다음 날 퇴근 예정시각을 같은 자료에 함께 저장한다. 휴무일에는 출근 예정시각을 만들지 않으며, 퇴근 예정시각만을 위한 별도 자료는 만들지 않는다. |

야간근무의 휴무일 판단은 공휴일 API에서 내려온 날짜 자체가 아니라 공휴일 관리 목록에서 `선택` 값이 `Y`인 날짜를 기준으로 한다. 공휴일이지만 `N`으로 저장된 날짜는 자동 휴무 대상이 아니다. 수동 휴무일 지정은 **근무지배정 상세** 화면의 휴무일 캘린더에서 근무기간 안의 날짜를 선택해 저장하며, 저장된 날짜에는 근무자의 출근을 허용하지 않는다.

출퇴근 예정시각은 직원·근무일별 통합 테이블인 `work_record`의 `intime`, `outtime`에 저장되며, 실제 출퇴근 시각(`work_intime`, `work_outtime`)과 함께 출결 등록·근태 판정의 기준으로 사용한다. 배정 저장 후 **근무지배정 상세** 화면의 달력에서 날짜별 출근·퇴근 예정시각과 휴무일 표시를 확인한다.

#### 2.1.2 관리자 상세 화면 명칭

목록에서 자료를 선택해 확인·수정하는 화면은 다음 명칭으로 표시한다.

| 대상 | 화면 제목 |
| --- | --- |
| 직원 | 직원 상세 |
| 근무지 | 근무지 상세 |
| 근무지 배정 | 근무지배정 상세 |
| 교육자료 | 교육자료 상세 |
| 근태 기록 | 근태 상세 |
| 시스템 설정 | 시스템설정 상세 |

따라서 배정의 날짜별 예정시각과 휴무일을 확인할 때는 **근무지배정 상세** 화면을 사용한다.

### 2.2 근태

- 대시보드에서 당일 출근·결근·지각 현황을 확인한다.
- 근태 리포트의 직원명·연도 조건으로 이력을 조회한다.
- GPS 오류 신고 시 기기 위치 권한, 당일 배정, 근무지 좌표와 반경을 순서대로 점검한다.

#### 2.2.1 대시보드 출근현황 카드의 출근·지각·결근·대기 집계 기준

대시보드 첫 번째 **출근현황** 카드의 분모는 현재 재직 직원 전체가 아니다. `work_record`에서 오늘 날짜(`work_date`)의 출근 예정시각(`intime`)이 있는 재직 직원만 집계하며, 직원 ID 기준으로 중복을 제거한다.

| 카드 항목 | 산출 기준 |
| --- | --- |
| 출근 | 오늘 출근 예정인 재직 직원 중 예정 출근시각과 같거나 이르게 출근한 직원 수 |
| 지각 | 오늘 출근 예정인 재직 직원 중 예정 출근시각보다 늦게 출근한 직원 수 |
| 결근 | 출근 예정시각이 현재 시각보다 이전이고, 해당 직원의 오늘 출근 근태자료가 없는 재직 직원 수 |
| 대기 | 출근 예정시각이 현재 시각과 같거나 이후이고, 해당 직원의 오늘 출근 근태자료가 없는 재직 직원 수 |
| 합계 기준 | `출근 + 지각 + 결근 + 대기`는 오늘 출근 예정인 재직 직원 수와 일치한다. 직원 ID 기준으로 한 번만 집계한다. |

따라서 카드에는 `출근 X 지각 Y 결근Z 대기 W` 형식으로 표시된다. 예를 들어 `출근 1 지각 1 결근1 대기 1`은 정시 출근 1명, 지각 1명, 예정시각이 지난 결근 1명, 아직 예정시각 전이라 대기 중인 직원 1명이라는 뜻이다. 휴무일 등으로 해당 날짜의 `intime`이 없는 배정은 집계하지 않는다.

카드의 `출근`은 퇴근 여부와 관계없이 예정시각 이내 출근자료가 있는 인원을 뜻한다. `현재 출근` 카드의 미퇴근 인원과는 다른 지표다. 대기·결근·지각·출근은 서로 중복하지 않도록 직원별로 하나의 상태만 부여하며, 이 기준은 직원관리 화면의 재직 직원 수 및 최근 30일 추이 차트의 전체 재직 직원 기준과 다를 수 있다.

#### 2.2.2 근태관리의 `지각` 판정 기준

근태관리 목록은 다음 조건을 모두 만족하는 배정의 예정 출근시각과 실제 출근일시를 비교한다.

1. 같은 직원이다.
2. 같은 근무지이다.
3. 같은 근무일이다.
4. 해당 날짜의 배정별 예정 출근시각(`intime`)이 존재한다.

실제 출근일시가 예정 출근시각보다 늦으면 목록의 상태에 `지각`을 표시한다. 예정시각과 같거나 이르면 `지각`으로 표시하지 않는다. 예정 출근시각이 없는 휴무일, 배정과 일치하지 않는 근태기록, 출근일시가 없는 기록은 지각으로 판정하지 않는다. 근태기록을 수정한 경우 다음 목록 조회에서 수정된 출근일시를 기준으로 다시 판정하며, 엑셀 다운로드에도 동일한 상태가 포함된다.

#### 2.2.3 출근현황 목록의 상태 표시

**출근현황** 화면은 날짜를 기준으로 `work_record`에 출근 예정시각(`intime`)이 있는 재직 직원만 목록에 표시한다. 목록의 `출근시각`은 같은 행의 실제 출근시각(`work_intime`)이며, 자료가 없으면 `-`로 표시한다.

| 상태 | 표시 기준 |
| --- | --- |
| 출근 | 실제 출근일시가 예정 출근시각과 같거나 이른 경우 |
| 지각 | 실제 출근일시가 예정 출근시각보다 늦은 경우 |
| 대기 | 출근 근태자료가 없고 출근 예정시각이 현재 시각과 같거나 이후인 경우 |
| 결근 | 출근 근태자료가 없고 출근 예정시각이 현재 시각보다 이전인 경우. 기존 `미출근` 표기를 `결근`으로 변경했다. |

목록은 출근 예정시각이 빠른 순서로 정렬하며, 같은 시각에는 직원 이름순으로 표시한다. 목록의 `대기`·`결근` 표시는 출근자료 유무와 현재 시각을 함께 반영하며, 대시보드 카드의 결근 수는 현재 시각이 예정 출근시각을 지났는지까지 확인해 집계한다.

#### 2.2.4 근무자 홈의 근무일·시간 표시 및 출퇴근 기준

근무자 홈(`/guard/main`)의 `오늘 근무` 카드와 출퇴근 동작은 한국시간 기준으로 조회한 해당 근무자의 `work_record`를 기준으로 한다. 조회 대상은 `work_date`가 오늘인 기록과 예정 퇴근일시(`outtime`)의 한국 날짜가 오늘인 기록이다. 조회 범위에는 근무자의 모든 근무지가 포함된다. 자정을 넘기는 근무는 퇴근 예정일이 오늘이어도 근무일(`work_date`)을 날짜로 표시한다.

| 카드 항목 | 표시 기준 |
| --- | --- |
| 근무 없음 | 조회 결과가 없으면 날짜 위치에 `오늘 근무가 없습니다.`를 표시하고 시간과 근태 상태를 숨긴다. 출퇴근, 특이사항, 순찰, 점검 진입점을 비활성화한다. 안전교육과 근무정보 메뉴는 사용할 수 있다. |
| 근무일 | 선택된 기록의 `work_date`를 `MM/DD (요일)` 형식으로 표시한다. 예: `10/28 (금)` |
| 예정 시간 | 선택된 기록의 예정 `intime`과 `outtime`을 한국시간 12시간 형식으로 표시한다. 예: `10:00 PM - 6:00 AM`. 실제 처리시각이나 배정의 기본 시간으로 대체하지 않는다. |
| 출근하기 | 선택된 기록에 실제 출근시각(`work_intime`)이 없고 실제 퇴근시각(`work_outtime`)도 없으면 표시한다. 출근 요청은 선택된 `work_date`의 기록을 처리한다. |
| 퇴근하기 | 선택된 기록에 `work_intime`은 있고 `work_outtime`은 없으면 표시한다. 퇴근 요청은 같은 선택 근무일의 기록을 처리한다. |
| 근무 완료 | 선택된 기록에 `work_outtime`이 있으면 완료 상태로 표시하고 출퇴근 동작을 비활성화한다. |

대상 기록이 여러 건이면 `work_date` 오름차순으로 정렬한 뒤 퇴근 처리(`work_outtime`)가 되지 않은 가장 앞선 기록을 선택한다. 퇴근 처리 후 세션을 다시 조회하므로 다음 미퇴근 근무일이 선택된다. 미퇴근 기록이 없으면 가장 마지막 `work_date`를 표시하고 근무 완료 상태로 처리한다. 선택된 기록의 근무지를 위치 확인에 사용한다.

#### 2.2.5 근무일별 출근상태와 휴가 반영 {#attendance-status-and-leave}

`work_record`의 `work_date`는 근무 기준일이며, `intime_status`는 해당 근무일의 출근상태를 문자열 코드로 저장한다.

| `intime_status` | 의미 | 적용 기준 |
| --- | --- | --- |
| `'0'` | 미출근 | 근무예정 생성 시 기본값. 아직 출근 처리되지 않은 상태 |
| `'1'` | 지각 | 실제 출근일시가 출근 예정일시보다 늦은 상태 |
| `'2'` | 출근 | 정상 출근으로 처리된 상태 |
| `'3'` | 휴가 | 휴가 신청으로 처리된 상태 |

`'0'`만으로 최종 결근을 의미하지는 않는다. 화면의 대기·결근 표시는 실제 출근자료 유무와 출근 예정시각, 조회 시점 등을 함께 판단한다. `'3'`은 정상근무 완료가 아니라 휴가를 뜻하며, 실제 퇴근 여부는 `work_outtime`과 `outtime_status`로 확인한다.

**휴가신청**(`/manager/leave/new`)에서 저장하면 `create_leave_with_attendance` DB 함수가 휴가를 `leave` 테이블에 등록하고, 다음 조건을 모두 만족하는 기존 `work_record` 행을 수정한다.

- `employee_id`가 신청한 직원과 같다.
- `work_date`가 휴가 시작일부터 종료일까지에 포함된다. 시작일과 종료일도 포함한다.
- `intime_status`가 `'0'`이다.

| 변경 컬럼 | 저장 값 |
| --- | --- |
| `intime_status` | `'3'`(휴가) |
| `updated_at` | 저장 시점의 DB 현재 시각 |

출퇴근 예정일시(`intime`, `outtime`), 실제 출퇴근일시(`work_intime`, `work_outtime`), 퇴근상태(`outtime_status`)는 변경하지 않는다. 근태 행이 없는 날짜에는 새 행을 만들지 않으며, 해당 기간에 근태 행이 없어도 휴가 자체는 등록할 수 있다. 휴가종류와 시작일·종료일은 `leave` 테이블에 보관한다.

같은 직원의 기존 휴가기간과 하루라도 겹치면 `휴가신청기간이 겹칩니다.` 오류로 신청을 중단한다. 신청기간 내 근태 행에 `'0'`이 아닌 출근상태(`'1'`, `'2'`, `'3'`)가 하나라도 있으면 해당 날짜의 출근정보가 있다는 오류로 신청 전체를 중단하며, 휴가 등록과 근태 변경을 모두 반영하지 않는다.

휴가를 삭제하면 해당 직원·휴가기간의 기존 근태 행 중 `'3'`을 `'0'`으로 되돌리고 `updated_at`을 갱신한다. 다만 다른 휴가가 해당 날짜를 포함하면 `'3'`을 유지한다. 이 규칙은 휴가 신규 신청과 삭제에 해당하며, 기존 휴가 상세에서 기간을 수정하는 동작은 `leave`만 변경하고 근태 상태를 자동으로 재반영하지 않는다.

### 2.3 안전교육

- 교육 제목과 재생 가능한 영상 링크를 등록한다.
- 직원별 전체·이수·미이수 건수를 확인한다.
- 미이수 알림 발송 전 대상 인원과 구독 상태를 확인한다.
- 자동 발송 실패 시 실행 이력의 오류 사유를 확인하고 수동 발송을 검토한다.

#### 2.3.1 일일·월별교육이수 목록의 조회 조건 {#education-attendance-filters}

일일교육이수(`/manager/safety/daily_edu`)와 월별교육이수(`/manager/safety/monthly_edu`)는 모두 `work_record`에 실제 출근일시(`work_intime`)가 있는 기록을 대상으로 한다. 날짜·시각의 조회 경계는 한국시간 기준이며, 목록별 기준은 다음과 같다.

| 목록 | 조회 대상 근태 조건 | 표시 단위 |
| --- | --- | --- |
| 일일교육이수 | `work_intime`이 있고, 실제 출근일시(`work_intime`) 또는 예정 퇴근일시(`outtime`)가 조회일 00:00 이상, 다음 날 00:00 미만인 기록 | 직원별 한 행. 해당 직원의 대상 기록이 여러 건이면 가장 최근 `work_date`를 출근일로 표시 |
| 월별교육이수 상단 현황 | `work_intime`이 있고, 실제 출근일시(`work_intime`) 또는 예정 퇴근일시(`outtime`)가 조회월 1일 00:00 이상, 다음 달 1일 00:00 미만인 기록 | 직원별 한 행 |
| 월별교육이수 하단 ‘월별 일일교육이수 기록’ | `work_intime`이 있고, 근무일(`work_date`)이 조회월에 속하는 기록 | 직원·근무일별 한 행 |

일일 목록과 월별 상단 현황은 같은 조회 조건을 사용하며, 범위만 하루와 한 달로 다르다. 이 두 목록은 `work_date`가 조회일·조회월과 같은지를 직접 조건으로 삼지 않는다. 반면 월별 하단 기록은 `work_date`로 조회하고, 실제 출근일시가 조회월 안에 있는지는 별도로 제한하지 않는다. 어느 목록도 실제 퇴근일시(`work_outtime`)를 날짜 범위 조건으로 사용하지 않는다.

예를 들어 실제 출근일시가 **9월 30일 22:00**, 예정 퇴근일시가 **10월 1일 06:00**, 근무일(`work_date`)이 **9월 30일**이면 다음과 같이 조회된다.

- 10월 1일 일일교육이수 목록: 예정 퇴근일시가 조회일에 포함되므로 표시하며, 출근일은 `09월 30일`에 해당하는 `work_date` 값을 표시한다.
- 10월 월별교육이수 상단 현황: 예정 퇴근일시가 조회월에 포함되므로 직원 대상에 포함한다.
- 10월 월별교육이수 하단 기록: 근무일이 9월이므로 해당 근무기록을 제외한다. 이 기록은 9월 하단 기록에 포함한다.

따라서 월별 상단 현황과 하단 기록의 직원 수·근무일 수가 다를 수 있다. 일일 목록의 ‘출근일’도 실제 출근일시에서 날짜를 잘라 표시하는 값이 아니라 `work_date`다.

#### 2.3.2 교육 이수 판정과 월별 이수율

목록의 직원 조회 조건과 교육 이수 여부를 판단하는 날짜 조건은 구분해서 확인한다. 교육 이수는 직원 ID·교재 제목·교육구분이 일치하는 `education_completions` 기록을 기준으로 한다. 화면의 ‘연간’은 저장된 교육구분 ‘기타’에 해당한다.

| 구분 | 교재 대상 및 이수 판정 기준 |
| --- | --- |
| 일일교육이수의 일일교육 | 조회일이 교재 적용기간(`startdate`~`enddate`, 양 끝 포함)에 속하고, 이수 기록의 `work_date`가 조회일과 같으면 이수 |
| 일일교육이수의 월별·분기·반기·연간교육 | 조회일에 적용되는 교재에 대해, 교재 시작일부터 조회일까지의 `work_date`로 저장된 이수 기록이 있으면 이수. 조회일 이후 또는 교재 적용기간 이전 기록은 제외 |
| 월별교육이수 상단의 월별·분기·반기·연간교육 | 적용기간이 조회월과 하루라도 겹치는 교재를 대상으로, 조회월 안의 `work_date`로 저장된 이수 기록이 있으면 해당 교재를 이수로 집계 |
| 월별교육이수 하단의 일일교육 | 해당 행의 `work_date`가 교재 적용기간 안에 있으면 같은 직원·근무일·교재의 일일교육 이수 기록 유무로 `O` 또는 `X` 표시. 적용기간 밖은 `-` 표시 |

일일 목록과 월별 상단의 월별·분기·반기·연간 표시는 해당 구분에서 이수한 교재가 1건 이상이면 `O`, 없으면 `X`이며, 대상 교재가 없으면 `-`다. 월별 상단의 일일교육은 직원별 대상 교재·근무일 조합의 `이수 건수/대상 건수`를 표시한다. 월별 상단의 기간교육은 분기·반기·연간 전체 기간을 조회하는 방식이 아니라 **조회월 안의 이수 기록**을 집계하므로, 일일 화면의 기간교육 판정과 다를 수 있다.

월별 화면 상단의 이수율은 다음과 같이 계산한다.

- 분모: 상단 현황 직원 수 × 조회월과 적용기간이 겹치는 월별·분기·반기·연간 교재 수의 합계 + 하단 일일교육의 적용 대상 교재·근무일 건수.
- 분자: 상단 기간교육의 이수 교재 건수 합계 + 하단 일일교육의 이수 건수.
- 분모가 0이면 0%를 표시하며, 그 외에는 백분율을 소수점 이하 반올림한다. 이름 검색 시에는 필터링된 목록을 기준으로 계산한다.

### 2.4 점검과 특이사항

- 점검 현장은 근무지와 현장명만 등록한다. 현장 주소와 현장 GPS는 입력하거나 저장하지 않는다. 점검 이력의 좌표 스냅샷은 연결된 근무지 GPS를 사용하며, 등록된 현장의 QR/NFC 정보를 생성해 사용한다.
- 점검 이력은 최신 순으로 확인하고 필요 시 근무지로 필터링한다.
- 특이사항 보고의 내용, 사진, 위치와 Naver mail 전달 상태를 확인한다.
- 보고 삭제 시 연결 사진도 함께 삭제되므로 대상 내용을 다시 확인한다.

## 8. 로그인 세션 관리 안내

### 8.1 로그인 방법

| 구분 | 로그인 방법 |
| --- | --- |
| 근무자 | 이름과 연락처로 로그인 |
| 관리자 | 등록된 Google 계정으로 로그인 |

등록되지 않았거나 이용 권한이 없는 사용자는 로그인할 수 없다.

### 8.2 로그인은 얼마나 유지되나요?

근무자와 관리자 모두 브라우저나 탭을 닫아도 로그인 상태가 유지된다. 같은 브라우저에서 다시 접속하면 별도의 로그인 없이 이전 화면을 계속 이용할 수 있다.

로그인 상태에는 정해진 만료 시간을 두지 않는다. 다만 다음 조건이 모두 충족되어야 자동 로그인이 유지된다.

- 브라우저에 로그인 정보가 남아 있어야 한다.
- 근무자 또는 관리자 권한이 계속 유효해야 한다.
- 인증 정보에 보안상 문제가 없어야 한다.

접속할 때마다 현재 이용 권한을 확인하고, 근무자의 배정 근무지와 근태 정보도 최신 내용으로 갱신한다.

### 8.3 언제 다시 로그인해야 하나요?

다음과 같은 경우에는 로그인 화면이 다시 나타날 수 있다.

- 사용자가 직접 로그아웃한 경우
- 브라우저의 쿠키나 사이트 데이터를 삭제한 경우
- 시크릿 모드를 종료한 경우
- 다른 기기 또는 관리 기능에서 인증이 해제된 경우
- 저장된 로그인 정보가 손상되었거나 보안상 사용할 수 없게 된 경우

인터넷 연결이 일시적으로 끊어진 경우에는 저장된 로그인 정보를 바로 삭제하지 않는다. 연결이 복구되면 다시 접속하여 이용 권한을 확인한다.

### 8.4 퇴직·삭제·권한 회수 시에는 어떻게 되나요?

로그인 상태가 남아 있어도 현재 이용 권한이 없으면 시스템을 사용할 수 없다.

| 상황 | 처리 결과 |
| --- | --- |
| 근무자가 퇴직 처리되거나 삭제됨 | 근무자 화면과 업무 기능 이용 차단 |
| 관리자가 삭제되거나 권한이 회수됨 | 관리자 화면과 관리 기능 이용 차단 |
| 권한이 다시 부여됨 | 보안을 위해 다시 로그인 |

근무자의 경우 이용할 수 없는 상태가 확인되면 저장된 로그인 정보를 지우고 로그인 화면으로 이동한다. 관리자는 등록된 관리자 권한이 확인되지 않으면 관리자 화면에 들어갈 수 없다.

### 8.5 로그아웃하면 어떻게 되나요?

근무자가 로그아웃하면 저장된 로그인 정보와 알림 연결 정보를 정리한 후 근무자 로그인 화면으로 이동한다.

관리자가 로그아웃하면 관리자 인증을 종료한 후 관리자 로그인 화면으로 이동한다.

공용 PC나 다른 사람과 함께 사용하는 기기에서는 브라우저만 닫지 말고 반드시 **로그아웃**해야 한다.

### 8.6 자동 로그인이 되지 않을 때

다음 사항을 순서대로 확인한다.

1. 인터넷 연결을 확인하고 다시 접속한다.
2. 올바른 이름·연락처 또는 등록된 Google 계정을 사용했는지 확인한다.
3. 브라우저에서 쿠키와 사이트 데이터 저장이 차단되어 있지 않은지 확인한다.
4. 퇴직, 계정 삭제 또는 권한 회수 여부를 관리자에게 문의한다.
