# 직원별 요일·공휴일 근무시간

직원등록·직원수정에서 기본 출퇴근시간과 평일, 토요일, 일요일, 공휴일의 적용 방식을 입력한다.

휴무일은 월요일부터 일요일까지 각 요일과 공휴일을 체크박스로 복수 선택한다. 예를 들어 매주 화요일 휴무는 화요일만, 월·화 휴무는 두 요일을 함께 선택한다. 배정등록에서도 직원 설정을 불러와 같은 방식으로 조정할 수 있다.

- 기본 설정 사용: 기본 출퇴근시간으로 근무한다.
- 별도 시간 지정: 해당 구분의 출퇴근시간으로 근무한다.
- 휴무: 예정 근태를 생성하지 않고 배정의 휴무일에 등록한다.
- 선택한 요일은 국공휴일과 겹쳐도 휴무다. 출근하는 국공휴일의 시간은 공휴일 규칙을 우선하며, 공휴일 규칙이 없으면 기본시간을 사용한다.
- 선택된 회사 지정 휴일은 휴무다. 선택 해제된 휴일은 계산에서 제외한다.
- 격일근무는 배정 시작일부터 짝수 번째 날짜에만 출근하며, 휴무 때문에 주기를 이동하지 않는다.
- 야간·격일근무의 익일 퇴근은 출근일 기준 분 단위로 저장한다. 다음 날 06:00은 30:00(1800분)이다.

예: A/B 직원은 기본 07:00, 토요일 별도 08:00으로 설정한다. C 직원은 기본 16:00, 공휴일 별도 08:00으로 설정한다. 각 설정에 퇴근시간도 입력한다. 지정하지 않은 일요일 등의 근무 여부는 별도로 결정한다.

## 저장 및 적용 시점

`employees.in_time/out_time`은 기본시간이다. `employee_schedule_rules`는 직원의 예외 규칙이며 `(employee_id, day_type)`은 유일하다. 규칙이 없으면 기본시간을 사용하므로, 휴무는 반드시 `is_working_day=false` 규칙으로 표현한다.

`day_type`은 `weekday`, `monday`~`sunday`, `holiday`를 지원한다. 월~금의 개별 요일 규칙이 있으면 해당 날짜의 `weekday` 규칙보다 우선한다. 개별 휴무 선택은 각각 별도 행으로 저장하며, 기존 규칙과 근태를 일괄 변경하지 않는다.

직원과 규칙은 `save_employee_with_schedule` RPC에서 한 트랜잭션으로 저장한다. 오류가 발생하면 양쪽 변경을 모두 취소한다. 관리자 인증을 거친 서버의 service role만 규칙 테이블과 저장 RPC에 접근한다.

배정등록은 직원 설정을 가져와 배정에 맞게 조정할 수 있다. `create_assignment_with_schedule_rules`가 기본시간과 근무형태를 배정에 저장하고, 예외를 `assignment_schedule_rules`에 복사한다. 직원 설정을 나중에 변경해도 이미 저장한 배정의 규칙은 변경되지 않는다. 기존 배정의 시간을 바꾸려면 별도의 배정 수정 작업이 필요하다.

새 배정의 근태 생성은 날짜에 맞는 규칙을 적용해 `work_record.intime/outtime`에 예정시간을 저장한다. 지각·조퇴 판정은 이 예정시간과 실제 출퇴근시간을 비교하는 기존 흐름을 사용한다. 재생성할 때 과거 기록 및 실제 출퇴근이 있는 기록은 변경하지 않는다. 직접 지정한 휴무일도 보존한다.

## 기존 데이터 호환

마이그레이션은 기존 배정의 비어 있는 기본시간·근무형태·휴무 설정을 현재 직원 값으로 확정한다. 기존 근태를 재생성하거나 직원별 규칙을 임의로 만들지 않는다.

`schedule_rules_enabled=false`인 기존 배정은 이전 근태 생성 함수를 계속 사용한다. 기존 직원의 `has_weekend=true`는 편집 화면에서 토요일·일요일·공휴일 휴무로 표시한다. 저장 이후에는 새 규칙 방식으로 처리한다. 새 규칙 방식의 배정에서는 명시한 날짜별 근무 여부를 적용하며, 기존 야간근무의 배정 시작일 휴일 예외를 자동으로 추가하지 않는다.

구분이 없던 기존 공휴일은 종전 동작을 유지하도록 `holiday_type=public`으로 전환한다. 회사 지정 휴일이 섞여 있다면 공휴일관리에서 구분을 변경한다. 새 수동 휴일의 기본 구분은 회사 지정 휴일이며, 공공데이터 가져오기는 국공휴일로 저장한다. 기존 날짜의 선택값과 구분은 가져오기로 덮어쓰지 않는다. 휴일 변경은 이미 생성된 근태를 자동으로 다시 계산하지 않으며, 새 배정 또는 미래 미출근 일정의 재생성 시 반영된다.

## 검증

- 직원등록·수정, 배정등록·상세, 휴일 API 및 공통 입력 컴포넌트의 Vitest 테스트.
- `supabase/tests/employee_schedule_rules.sql`: 격리된 테스트 DB에 스키마 적용 후 실행한다. 평일 기본시간, 토요일 예외, 공휴일 우선순위, 회사 휴일, 야간·격일, 배정 스냅샷, 과거/실제출근 기록 보존, 중복 규칙의 트랜잭션 취소, 기존 생성기, 접근 권한을 확인한다. 테스트 데이터는 롤백한다.
- `supabase/tests/weekly_days_off.sql`: 일요일·공휴일, 주말, 주말·공휴일, 화요일, 월·화요일 휴무 조합과 공휴일 중복, 개별 요일 우선순위 및 배정 설정 보존을 확인하고 롤백한다.
- 데스크톱 및 390px 모바일에서 실제 페이지 컴포넌트를 모의 API로 렌더링해 입력·저장 요청과 가로 넘침을 확인했다.

배포 순서는 DB 마이그레이션 적용 후 애플리케이션 배포다. 새 테이블과 RPC가 없으면 새 화면의 저장이 실패한다.
