## 1. 문서 목적 및 범위

본 문서는 올바름 인력관리시스템에서 제공하는 기능의 입력·처리·출력, 업무 규칙, 예외 조건을 정의한다. 후속 화면 명세서와 유지보수·테스트의 기준 문서로 사용한다.

본 문서에서 상태는 다음과 같이 구분한다.

- **구현**: 현재 서비스에서 제공하는 기능
- **부분 구현**: 핵심 흐름을 제공하되 일부 이용 조건이나 제약이 있는 기능
- **확장 구현**: 기본 업무와 함께 제공되는 인증·설치·외부 연동 등의 부가 기능

## 2. 시스템 구성 및 사용자

### 2.1 사용자 유형

| 사용자 | 인증 방식 | 주요 권한 |
| --- | --- | --- |
| 최고 관리자(`super_admin`) | 이메일 기반 관리자 인증 | 모든 관리자 기능, 관리자 계정 등록·역할 변경·삭제 |
| 일반 관리자(`admin`) | 이메일 기반 관리자 인증 | 대시보드, 직원·근무지·배정, 교육, 점검, 리포트, 로그·설정 조회/관리 |
| 현장 근무자 | 이름·연락처 간편 인증, 선택적으로 관리자 승인형 Passkey | 본인 배정·출퇴근·교육·점검·특이사항·프로필 처리 |

### 2.2 주요 업무 영역

| 영역 | 관리자 | 현장 근무자 |
| --- | --- | --- |
| 인증 | 관리자 로그인, 최초 관리자 등록, 관리자 계정 관리 | 간편 로그인, Passkey 신청·등록·로그인 |
| 인력 | 직원·퇴직·직무 관리 | 본인 정보 사용 |
| 근무 | 근무지·GPS·인정 반경·기간 배정 관리 | 오늘 배정 확인, 위치 기반 출퇴근 |
| 교육 | 자료·영상·이수율·알림 관리 | 영상 시청 및 이수 처리 |
| 점검 | 점검 현장·QR·이력 관리 | QR/NFC 점검 기록 |
| 보고 | 특이사항 목록·상세·삭제 | 음성·사진·위치를 포함한 특이사항 보고 |
| 리포트 | 근태·교육 이수 조회 및 XLS 다운로드 | 최근 1년 일정·월별 근태 확인 |
| 운영 | 로그, 설정, PWA | PWA 설치, 푸시 알림, 오프라인 안내 |

## 3. 공통 기능 명세

### COM-001 초기 진입 및 서비스 선택

- 상태: 구현
- 진입 경로: `/`
- 기능: 관리시스템과 현장 근무자용 화면의 진입점을 분리하여 제공한다.
- 결과: 관리자는 `/manager`, 근무자는 `/guard` 흐름으로 이동한다.

### COM-002 반응형 웹 및 PWA

- 상태: 확장 구현
- 관리자와 근무자 영역에 각각 전용 Web App Manifest를 제공한다.
- 서비스 워커를 통해 설치형 웹앱 동작과 오프라인 안내 화면을 제공한다.
- 관리자 영역은 모바일 햄버거 메뉴와 PC 사이드바를 제공한다.
- 인앱 브라우저에서는 기능 제약 안내 및 외부 브라우저 전환 가이드를 제공한다.

### COM-003 공통 오류 처리

- 필수 입력 누락, 형식 오류, 존재하지 않는 데이터, 권한 부족을 오류로 반환한다.
- 생성·수정 화면은 처리 결과를 사용자에게 안내하고 성공 시 목록 또는 상세 화면으로 이동한다.
- 삭제 작업은 확인 절차 후 수행한다.

## 4. 관리자 기능 명세

### ADM-001 관리자 인증 및 접근 통제

- 상태: 확장 구현
- 진입 경로: `/manager/auth`
- 입력: 관리자 이메일 및 인증 정보
- 처리:
  1. Supabase 인증 사용자를 확인한다.
  2. `admin_users`에 연결된 사용자만 보호된 관리자 화면에 접근시킨다.
  3. 미인증 사용자는 원래 요청 경로를 보존해 인증 화면으로 이동시킨다.
- 최초 관리자:
  - 관리자 계정이 없을 때 설정 코드로 최초 최고 관리자를 등록할 수 있다.
  - 이미 관리자가 존재하면 최초 등록 요청을 거부한다.
- 예외: 인증 정보가 없거나 관리자 등록이 확인되지 않으면 401 또는 인증 화면 이동 처리한다.

### ADM-002 관리자 계정 및 역할 관리

- 상태: 확장 구현
- 진입 경로: `/manager/system/admin-users`
- 조회: 관리자 이메일, 역할, 등록 상태를 목록으로 제공한다.
- 등록: 이메일과 `admin` 또는 `super_admin` 역할을 입력한다.
- 수정·삭제: 최고 관리자만 역할 변경과 삭제를 수행할 수 있다.
- 업무 규칙:
  - 일반 관리자가 계정 변경 API를 호출하면 403을 반환한다.
  - 중복 이메일과 유효하지 않은 역할을 거부한다.
  - 관리자 초대/사전 등록 정보는 실제 인증 사용자와 연결된다.

### ADM-003 대시보드

- 상태: 구현
- 진입 경로: `/manager`
- 요약 지표:
  - 퇴직자를 제외한 전체 재직 인원
  - 금일 출근 후 미퇴근인 현재 출근 인원
  - 전체 교육자료 중 하나 이상 미이수한 재직 인원
- 차트:
  - 최근 일자별 출근 현황
  - 일자별 전체 교육자료 이수 현황
- 현황 목록:
  - 근무자명, 근무지, 출근 시각, 교육 완료 여부, 출근 상태
- 산정 규칙:
  - 교육자료가 없으면 교육 미이수 인원은 0명으로 계산한다.
  - 출근 현황은 당일 근태와 유효한 배정 정보를 기준으로 조합한다.

### ADM-010 직원 목록 조회

- 상태: 구현
- 진입 경로: `/manager/employee/employees`
- 조회 항목: 이름, 연락처, 직무, 퇴직 여부, 등록일
- 정렬·검색: 목록 화면에서 조회 조건 및 정렬 가능한 열을 제공한다.
- 직무 값: 경비원, 미화원, 파견

### ADM-011 직원 등록

- 상태: 구현
- 진입 경로: `/manager/employee/employees/new`
- 필수 입력: 이름, 연락처
- 선택 입력: 직무(기본값 경비원)
- 처리:
  - 연락처에서 숫자만 추출한 정규화 값을 함께 저장한다.
  - 이름과 정규화 연락처 조합이 같으면 기존 레코드를 기준으로 처리한다.
  - 신규 직원은 재직 상태로 저장한다.
- 예외: 빈 이름·연락처, 허용되지 않은 직무는 저장하지 않는다.

### ADM-012 직원 수정 및 삭제

- 상태: 구현
- 진입 경로: `/manager/employee/employees/save/{id}`
- 수정 항목: 이름, 연락처, 직무, 퇴직 여부
- 삭제: 확인 후 직원 레코드를 삭제한다.
- 영향: 퇴직자는 근무자 인증과 Passkey 신청이 제한되며 대시보드·교육 리포트의 재직자 집계에서 제외된다.

### ADM-020 근무지 관리

- 상태: 구현
- 경로:
  - 목록 `/manager/employee/worksites`
  - 등록 `/manager/employee/worksites/new`
  - 수정 `/manager/employee/worksites/save/{id}`
- 입력: 근무지명, 주소, 위도, 경도, 출근 인정 반경(m)
- 보조 기능: 주소 검색, 주소-좌표 변환 및 지도 기반 GPS 선택을 지원한다.
- 검증:
  - 모든 핵심 항목은 필수이다.
  - GPS는 유효한 위도·경도 구조여야 한다.
  - 인정 반경은 숫자로 입력하며 최소 1m의 정수로 저장한다.
- 제공 기능: 목록 조회, 등록, 수정, 삭제

### ADM-030 근무 배정 관리

- 상태: 구현
- 경로:
  - 목록 `/manager/employee/assignments`
  - 등록 `/manager/employee/assignments/new`
  - 수정 `/manager/employee/assignments/save/{id}`
- 입력: 직원, 근무지, 시작일, 종료일
- 기본값: 날짜 미입력 시 당일을 시작일·종료일로 사용한다.
- 검증:
  - 시작일은 종료일보다 늦을 수 없다.
  - 같은 직원의 기존 배정 기간과 하루라도 겹치면 등록·수정을 거부한다.
  - 수정 시 자기 자신을 제외한 다른 배정과 중복 여부를 검사한다.
- 제공 기능: 전체 배정 목록 조회, 등록, 수정, 삭제

### ADM-040 안전교육 자료 관리

- 상태: 구현
- 경로:
  - 목록 `/manager/safty/resources`
  - 등록 `/manager/safty/resources/new`
  - 수정 `/manager/safty/resources/save/{id}`
- 입력: 교육 제목, 영상 URL 또는 영상 식별 정보
- 처리: 교육자료를 등록·조회·수정하며 근무자 교육 화면에 노출한다.
- 영상 연동:
  - 외부 영상 링크를 지원한다.
  - Cloudflare Stream의 직접 업로드, 영상 목록, 처리 상태 확인, 재생 화면을 별도로 제공한다.

### ADM-041 교육 이수 현황

- 상태: 구현
- 경로:
  - 요약 `/manager/safty/completions`
  - 상세 `/manager/safty/completions/detail`
- 조회 내용: 직원별 전체 교육 수, 이수 수, 미이수 수, 자료별 이수 여부·이수 시각
- 산정 규칙: 직원과 모든 교육자료의 조합을 기준으로 이수 레코드를 비교한다.

### ADM-042 교육 미이수 알림

- 상태: 구현
- 경로: `/manager/safty/notifications`
- 수동 발송:
  - 미이수 직원과 미이수 건수를 기준으로 푸시 알림을 발송한다.
  - 구독 정보가 없는 직원은 미수신 대상으로 처리한다.
- 자동 발송:
  - Cron API와 Supabase 예약 작업을 통해 교육 독려 알림을 실행한다.
  - 실행 비밀값이 올바르지 않으면 예약 API 호출을 거부한다.
- 결과 관리:
  - 상태는 처리중, 성공, 실패, 건너뜀으로 구분한다.
  - 알림 코드와 상태로 실행이력을 필터링할 수 있다.
  - 만료된 브라우저 구독은 발송 실패 시 정리할 수 있다.

### ADM-050 점검 현장 관리

- 상태: 구현
- 경로:
  - 목록 `/manager/inspection/sites`
  - 등록 `/manager/inspection/sites/new`
  - 상세·수정 `/manager/inspection/sites/{id}`
- 입력: 연결 근무지, 현장명, 주소, GPS 좌표
- 기능:
  - 현장명 검색, 등록, 수정, 삭제
  - 시스템 전용 형식과 버전을 포함한 QR 페이로드 생성
  - QR 이미지 저장
  - NFC에 기록하거나 링크로 사용할 수 있는 점검 주소 제공
- QR 데이터: 현장 ID, 근무지 ID·명, 현장명, 현장 GPS 정보

- 필터: 근무지 기준 조회를 지원한다.

### ADM-052 특이사항 관리

- 상태: 구현
- 경로:
  - 목록 `/manager/inspection/special-remarks`
  - 상세 `/manager/inspection/special-remarks/{id}`

### ADM-060 근태 리포트

- 규칙: 시스템 코드는 공백이 아닌 유일한 식별값이어야 한다.

### ADM-072 근무자 Passkey 승인 관리

- 상태: 확장 구현
- 진입 경로: `/manager/system/passkeys`
- 조회 항목: 신청자, 연락처, 퇴직 여부, 신청 상태, 신청·검토·등록·폐기 시각
- 상태: 대기, 승인, 거절, 등록 완료, 폐기
- 기능: 신청 승인, 거절, 등록된 Passkey 사용 폐기
- 규칙: 폐기 시 직원의 Passkey 사용 상태를 비활성화한다.

## 5. 현장 근무자 기능 명세

### GRD-001 간편 로그인

- 상태: 구현
- 진입 경로: `/guard`
- 입력: 이름, 연락처
- 처리:
  - 연락처의 숫자만 비교하는 정규화 방식으로 직원을 찾는다.
  - 이름과 연락처가 일치하고 퇴직자가 아니면 근무자 세션을 생성한다.
  - 브라우저 저장소에 근무자 식별 정보를 유지해 후속 화면에서 사용한다.
- 실패 조건: 미등록 사용자, 불일치 정보, 퇴직자는 로그인할 수 없다.

### GRD-002 Passkey 신청·등록·로그인

- 상태: 확장 구현
- 처리 흐름:
  1. 간편 인증한 근무자가 Passkey 사용을 신청한다.
  2. 관리자가 신청을 승인하거나 거절한다.
  3. 승인된 근무자가 기기에 Passkey를 등록한다.
  4. 이후 Passkey 세션으로 로그인한다.
- 규칙:
  - 퇴직자는 신청·등록할 수 없다.
  - 처리 대기 중인 중복 신청은 거부한다.
  - 승인 상태에서만 등록 자격 증명을 발급한다.
  - 등록 완료 또는 폐기 상태에서는 같은 승인 건을 재사용하지 않는다.

### GRD-003 메인 화면

- 상태: 구현
- 진입 경로: `/guard/main`
- 표시: 사용자 이름, 오늘 배정된 근무지, 현재 출근 상태
- 메뉴: 출퇴근, 안전교육, 현장점검, 특이사항, 개인 프로필
- 배정 규칙: 당일이 배정 시작일과 종료일 사이에 있는 배정을 오늘의 근무지로 판단한다.
- 예외: 유효한 배정이 없으면 관리자에게 근무지 배정을 요청하도록 안내한다.

### GRD-010 출근

- 상태: 구현
- 진입 경로: `/guard/main/attendance`
- 선행 조건: 로그인, 당일 유효 근무지 배정, 브라우저 위치 권한
- 입력: 근무자 ID, 근무지 ID, 현재 위도·경도
- 처리:
  1. 현재 위치와 근무지 GPS 간 거리를 계산한다.
  2. 거리가 근무지 인정 반경 이내인지 검사한다.
  3. 조건을 충족하면 당일 출근 시각과 출근 위치를 저장한다.
- 실패 조건:
  - 배정이 없음
  - 위치 정보가 없음
  - 인정 반경 밖
  - 이미 당일 출근 기록이 존재함
- 결과: 출근 성공 여부와 현재 근태 상태를 화면에 갱신한다.

### GRD-011 퇴근

- 상태: 구현
- 선행 조건: 당일 출근 기록이 있고 아직 퇴근하지 않은 상태
- 입력: 근무자 ID와 가능한 경우 현재 위치
- 처리: 퇴근 시각과 퇴근 GPS를 기존 당일 근태 레코드에 저장한다.
- 실패 조건: 출근 기록이 없거나 이미 퇴근 처리됨
- 구현 차이: 요구사항은 출근 위치 반경을 명시하지만 퇴근에는 동일 반경 제한을 강제하지 않는다.

### GRD-020 안전교육 조회 및 이수

- 상태: 구현
- 진입 경로: `/guard/main/safety`
- 조회: 등록된 교육자료와 본인의 이수 여부를 표시한다.
- 시청: 교육 영상 링크 또는 Cloudflare Stream 영상을 재생한다.
- 이수 처리: 근무자·교육자료 조합에 완료 상태와 완료 시각을 저장한다.
- 재처리: 이미 완료한 자료는 완료 상태로 표시하고 중복 완료를 방지한다.

### GRD-021 푸시 알림 구독

- 상태: 구현
- 선행 조건: 지원 브라우저, 알림 권한 허용, 서비스 워커 사용 가능
- 처리: 근무자 ID와 브라우저 PushSubscription을 등록한다.
- 변경: 같은 기기의 기존 구독을 정리하고 최신 구독으로 갱신한다.
- 해제: 근무자 기준으로 등록 구독을 해제할 수 있다.

### GRD-030 QR 현장점검

- 상태: 구현
- 진입 경로: `/guard/main/inspection`
- 입력: 카메라로 스캔하거나 직접 입력한 QR 데이터
- 검증:
  - 시스템 전용 타입이어야 한다.
  - QR 버전은 1이어야 한다.
  - 현장·근무지·GPS 필드가 유효해야 한다.
  - QR의 현장 ID가 실제 등록 현장과 일치해야 한다.
- 저장: 근무자 ID·명, 근무지, 현장, 현장 GPS, QR 원문, 점검 시각
- 직무 표시: 관리자는 직원 직무를 결합하여 경비원 순찰 또는 미화원 점검 이력을 구분할 수 있다.

### GRD-031 NFC 현장점검

- 상태: 구현
- 진입 경로: `/guard/main/inspection-nfc`
- 처리: NFC 태그에 기록된 점검 정보 또는 연결 주소를 읽어 동일한 현장점검 기록 흐름을 수행한다.
- 대체 수단: NFC 미지원 환경에서는 QR 점검을 사용할 수 있다.
- 구현 차이: 점검 시각과 현장 GPS 스냅샷은 저장하지만, 점검자의 실시간 GPS와 현장 반경 비교는 강제하지 않는다.

### GRD-040 특이사항 보고

- 상태: 구현
- 진입 경로: `/guard/main/special-remarks`
- 입력: 보고 내용, 선택 사진, 가능한 경우 현재 위치
- 입력 보조:
  - 브라우저 음성 인식으로 보고 내용을 입력할 수 있다.
  - 카메라 또는 파일 선택으로 사진을 첨부할 수 있다.
- 사진 규칙: 이미지 크기를 최대 500KB 기준으로 처리하고 전용 저장소에 저장한다.
- 저장 내용: 보고자, 근무지, 내용, 위도·경도, 사진 URL, 보고 시각, 이메일 전달 상태
- 외부 전달: 기본 보고 처리와 함께 Naver/Formspree 기반 전달 경로를 제공하며 성공·실패 상태를 기록한다.
- 위치를 얻지 못하더라도 가능한 정보로 보고를 계속할 수 있다.

### GRD-050 개인 프로필

- 상태: 구현
- 진입 경로: `/guard/main/profile`
- 근무 일정: 본인의 전체 배정 기간과 근무지명을 시작일순으로 표시한다.

  - 총 근무시간은 퇴근 완료 건의 출퇴근 시각 차이를 합산한다.
- 접근성: 화면 글자 크기 조절 기능을 제공한다.

### GRD-060 로그아웃

- 상태: 구현
- 처리: 현재 근무자 세션에 로그아웃 시각을 기록하고 브라우저의 근무자 상태를 정리한 뒤 로그인 화면으로 이동한다.

## 9. 수용 기준 요약

- 관리자는 인증 후 모든 관리 메뉴에 접근할 수 있고, 일반 관리자는 최고 관리자 전용 계정 변경을 수행할 수 없어야 한다.
- 재직 직원과 근무지를 등록한 후 겹치지 않는 기간으로 배정할 수 있어야 한다.
- 근무자는 이름·연락처로 인증하고 당일 배정 및 현재 출근 상태를 확인할 수 있어야 한다.
- 근무지 인정 반경 안의 위치에서만 출근 기록이 생성되어야 한다.
- 교육자료의 이수 결과가 근무자 화면, 관리자 현황, 대시보드, 리포트에 일관되게 반영되어야 한다.
- 시스템 전용 QR/NFC 정보로 생성된 점검만 등록 현장과 결합해 저장되어야 한다.
- 특이사항 보고는 내용과 선택 위치·사진을 저장하고 외부 전달 결과를 추적할 수 있어야 한다.
- 근태·교육 리포트는 조회 조건을 적용한 결과와 다운로드 파일의 내용이 일치해야 한다.
- 푸시 알림은 구독 보유자에게 발송되고 성공·실패·미수신 결과가 실행이력에 남아야 한다.
- 관리자와 근무자 화면은 모바일에서도 핵심 메뉴와 업무 처리가 가능해야 한다.
