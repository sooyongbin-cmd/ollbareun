올바름 인력관리시스템 코딩 가이드 ​

1. 기본 기준 ​

  • TypeScript strict 모드를 유지한다.
  • Next.js App Router와 React 함수형 컴포넌트를 사용한다.
  • 내부 모듈은 @/ 경로 별칭을 사용한다.
  • 코드·파일명은 영문, 사용자 화면 문구는 자연스러운 한국어를 사용한다.
  • 업무 규칙은 화면 컴포넌트가 아니라 src/lib에 배치한다.

2. 디렉터리 규칙 ​

위치용도
src/app페이지, 레이아웃, Route Handler
src/components여러 화면에서 재사용하는 UI
src/lib도메인 로직, 데이터 접근, 외부 연동
public이미지, 아이콘, 폰트 등 정적 자산
supabase/migrationsDB 변경 SQL
supabase/functionsSupabase Edge Function
docs요구·설계·운영 문서

3. 명명 규칙 ​

  • 컴포넌트와 타입은 PascalCase, 함수와 변수는 camelCase를 사용한다.
  • 파일과 URL 세그먼트는 소문자 kebab-case를 기본으로 한다.
  • DB 테이블·컬럼은 snake_case를 사용한다.
  • Boolean 값은 is, has, can 등 의미가 드러나는 접두사를 사용한다.

4. TypeScript와 React ​

  • any 사용을 피하고 API 입력은 unknown에서 검증한다.
  • 상태는 사용하는 컴포넌트 가까이에 두고, 공유가 필요한 경우에만 상위로 이동한다.
  • 서버에서 처리 가능한 데이터 조회는 서버 로직으로 유지한다.
  • 브라우저 API를 사용하는 컴포넌트에만 "use client"를 지정한다.
  • 비동기 실행 중 버튼을 비활성화하고 처리 상태를 표시한다.

5. API와 오류 처리 ​

  • Route Handler는 요청 파싱, 인증·입력 검증, 서비스 호출, HTTP 응답만 담당한다.
  • 정상 응답 키는 employee, rows, reports처럼 데이터 의미가 드러나게 한다.
  • 사용자 오류와 시스템 오류를 구분하고 내부 비밀정보를 응답에 포함하지 않는다.
  • 삭제 작업은 화면 확인 절차와 서버 검증을 모두 적용한다.

6. DB 접근 ​

  • 일반 데이터 접근은 공통 Supabase 클라이언트를 사용한다.
  • 서비스 역할이 필요한 작업은 서버 전용 관리 클라이언트만 사용한다.
  • DB 오류는 도메인에 맞는 사용자 메시지로 변환한다.
  • 스키마 변경은 기존 마이그레이션 수정 대신 새 마이그레이션으로 추가한다.

7. UI 작성 ​

  • 디자인 가이드.md와 src/app/globals.css의 공통 토큰을 따른다.
  • 버튼은 동작을 설명하는 텍스트 또는 접근성 이름을 가진 아이콘을 사용한다.
  • 폼은 라벨, 필수값, 검증 오류, 처리 결과를 제공한다.
  • 반응형 표와 모바일 터치 영역을 확인한다.

8. 테스트와 품질 ​

  • 기능 변경 시 정상, 입력 오류, 권한 오류, 외부 연동 실패 테스트를 추가한다.
  • 테스트 파일은 대상 파일 가까이에 *.test.ts 또는 *.test.tsx로 둔다.
  • 커밋 전 npm run lint, npm test, npm run build를 실행한다.
  • 생성 파일과 비밀정보는 커밋 대상에서 제외한다.

9. Git 규칙 ​

  • 한 커밋에는 하나의 명확한 목적을 담는다.
  • 커밋 메시지는 docs:, feat:, fix:, test: 등 변경 성격을 표시한다.
  • 사용자 작업과 무관한 파일을 함께 수정하거나 정리하지 않는다.
