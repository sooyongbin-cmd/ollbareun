로그인 세션 관리 ​

1. 목적 ​

근무자와 관리자의 로그인 상태는 사용자가 명시적으로 로그아웃할 때까지 유지한다. 다만 로그인 상태와 업무 권한은 분리하여, 퇴직·계정 삭제·관리자 권한 회수 시에는 저장된 세션이 남아 있더라도 서버가 접근을 거부한다.

2. 근무자 세션 ​

  • 근무자 세션은 브라우저 localStorage의 ollbareun.guard.session에 저장한다.
  • 기존의 마지막 활동 후 24시간 만료 정책은 사용하지 않는다.
  • 브라우저나 탭을 닫았다가 다시 열어도 세션을 복원한다.
  • 과거 sessionStorage에 저장된 세션은 localStorage로 이전하여 호환한다.
  • 메인 화면 진입 시 서버에서 직원 정보를 다시 조회하고 최신 배정·근태 정보를 반영한다.
  • 직원이 퇴직 또는 삭제된 경우 저장된 세션을 제거하고 근무자 로그인 화면으로 이동한다.
  • 출퇴근, 교육 이수, 현장점검, 특이사항 보고, Push 등록 등 주요 변경 API도 처리 전에 재직 상태를 확인하며, 권한이 없으면 HTTP 403으로 거부한다.
  • 로그아웃 시 근무자 로컬 세션, 레거시 세션, Push 등록 정보 및 Passkey용 Supabase 세션을 정리한다.

3. 관리자 세션 ​

  • 관리자 인증은 Supabase Auth의 access token과 refresh token을 사용한다.
  • 브라우저 종료 여부를 판단하던 sessionStorage 표식과 강제 로그아웃 게이트는 사용하지 않는다.
  • 브라우저를 다시 실행해도 Supabase refresh token이 유효하면 로그인 상태를 복원한다.
  • JWT 만료 시간을 무제한으로 늘리지 않고 짧은 access token을 refresh token으로 갱신한다.
  • 관리자 화면과 관리자 API는 요청마다 Supabase 사용자와 admin_users 등록 상태를 확인한다.
  • 관리자가 삭제되거나 권한이 회수되면 기존 브라우저 세션이 남아 있어도 접근을 거부한다.
  • 관리자 헤더의 로그아웃 버튼은 Supabase signOut()을 실행한 후 관리자 로그인 화면으로 이동한다.

4. 권한 회수 원칙 ​

무제한 로그인은 무제한 권한을 의미하지 않는다.

상태로그인 데이터서버 접근
정상 근무자·관리자명시적 로그아웃 전까지 유지허용
퇴직·삭제 근무자다음 서버 검증 시 제거거부
삭제·권한 회수 관리자Supabase 세션이 남을 수 있음admin_users 검증으로 거부
사용자가 로그아웃브라우저와 인증 세션 정리거부
브라우저 사이트 데이터 삭제세션 소실재로그인 필요

재입사 또는 관리자 권한 재부여 시에는 보안을 위해 다시 로그인한다.

5. Supabase 운영 설정 ​

Supabase Dashboard의 Authentication → Sessions에서 다음 항목을 확인한다.

  • Time-box user sessions: 비활성화
  • Inactivity timeout: 비활성화
  • Single session per user: 여러 기기에서 로그인 상태를 유지해야 하면 비활성화
  • JWT 만료 시간: 권장 기본값인 약 1시간 유지

비밀번호 변경, 보안상 민감한 작업, 세션 폐기 또는 Supabase 정책에 의해 refresh token이 무효화된 경우에는 다시 로그인해야 한다.

6. 검증 기준 ​

  • 근무자는 마지막 활동 후 24시간 이상 지나도 로그인 상태가 복원된다.
  • 관리자도 브라우저 종료 후 다시 접속했을 때 로그인 상태가 복원된다.
  • 퇴직·삭제된 근무자의 화면 진입과 주요 변경 API가 차단된다.
  • 삭제되거나 권한이 회수된 관리자의 보호 화면과 API 접근이 차단된다.
  • 근무자와 관리자의 명시적 로그아웃 이후 보호 화면에 다시 접근할 수 없다.

7. 빌드 ​

프로젝트의 npm run build는 다음 순서로 실행된다.

  1. npm run docs:build
  2. vitepress build docs --outDir public/docs/documents
  3. next build --webpack

따라서 전체 빌드를 실행하면 이 문서를 포함한 VitePress 결과물이 public/docs/documents에 먼저 생성된 후 Next.js production build가 실행된다.
